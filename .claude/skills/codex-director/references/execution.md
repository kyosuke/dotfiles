# herdr のペインで Codex を動かす

`../SKILL.md` の骨格から外れる操作が要るときに読む。分割幅、起動フラグ、承認の境界、並列の可否、報告回収の制約、ネットワーク、スレッドの分割と片付けを置く。詰まったときの復旧は `recovery.md`、実測の詳細は `evidence.md`。

**herdr そのものの操作は公式スキルに従う。** Skill ツールで `herdr` を呼ぶ（無ければ `herdr --skill` が同じ内容を出力する。バイナリが出力元なので本体の更新に追従する）。公式スキルの description は「ユーザーが herdr に言及したときだけ使う」と制限しているが、この委任経路は herdr のペイン操作そのものなので対象に入る。読むのは、骨格の範囲を超える操作が要るとき、または挙動がこのファイルの記述と食い違うとき。

ID の扱い、ペイン分割とエージェント名の規則、`idle` / `done` / `blocked` / `unknown` の意味と `--wait` / `--until` の使い分け、読み取り源4種（`visible` / `recent` / `recent-unwrapped` / `detection`）と代替画面の制約、閉じてよいペインの範囲は公式スキルにある。ここには書かない。読まずに想像で補わない。

## ペインを用意する

**分割方向は右を優先する（公式スキルの上書き）。** 公式スキルは「横に広ければ右、縦に長ければ下」と書くが、ユーザーの環境は横方向に余裕があり、左右に並べるほうが読みやすいという指定である。`--direction right` を既定にする。

分割後の幅が80桁を下回るなら `down` へ切り替える。80桁は実測の下限で、81桁でも Codex の TUI は崩れず報告も欠落なく回収できた。

2つ目以降のエージェントは右へ割り続けず、**最初に作ったエージェントペインを基準に下方向へ分割する。**

```bash
herdr pane split --pane <最初のエージェントのpane_id> --direction down --cwd "$PWD" --no-focus
```

幅は最初の分割で決まった値のまま維持されるので、80桁の下限の判断は1回で済む。減るのは行数なので、TUI が窮屈になったらそれ以上積まず、別タブへ移す。

## 起動フラグ

```bash
herdr agent start <名前> --kind codex --pane <pane_id> --timeout 60000 \
  -- --model <モデルID> -c model_reasoning_effort=<推論量> \
     -c service_tier=<priority / default> --no-alt-screen
```

`--` 以降が Codex のネイティブ引数になる。段の指定はここで渡す（`ordering.md`）。

- **`--no-alt-screen` を必ず付ける。** TUI を代替画面ではなくインラインで描くので、出力がスクロールバックに残り、報告の回収が確実になる。付けても `blocked` の検知は働き、ユーザーから見た表示も崩れない。
- ファイル変更にフラグは要らない。ユーザーの設定（`workspace-write`）で既定で書ける。調査だけを頼むなら `-s read-only` を付ける。
- ループバックを要する検証が発注に含まれるなら `-c sandbox_workspace_write.network_access=true` を足す（下記）。
- 承認方針は既定の `on-request` のまま起動する。`-a untrusted` は `codex --help` にある正式な値だが、trusted 集合（`ls`・`cat`・`sed` など）の外にあるコマンドをすべて承認へ上げる（`find` も対象になった）。ディレクターは承認できないので、そのペインでは作業が進まない。

## 発注する

```bash
herdr agent prompt <名前> "$(cat <scratchpad>/order.txt)" --wait --timeout 300000
```

依頼文は Write ツールでファイルへ書いてから渡す。ヒアドキュメントは使わない。理由は2つ。文中のバックティックがコマンド置換として実行される（実運用で `` `wrangler dev` `` が起動してサーバーとして残り、仕様の核が欠落した依頼文が渡った）。加えて、サンドボックスや権限に触れる文言を含むヒアドキュメントは Claude Code のclassifierに止められることがある。

戻った `agent_status` で分岐する。`agent get` を自分でポーリングしない。`idle` と `done` は区別せず、どちらも完了として報告を回収し検収へ進む。`blocked` は下記「承認を求められたとき」へ。

所要時間は、読み取りだけの小さな依頼で12〜40秒。実装を伴う依頼は20分を超えることがある。Bash ツールの上限は10分なので、長い依頼は `run_in_background: true` で投げ、完了通知を受けてから読む。

モデル名・推論量・オプションがこのファイルの記述と食い違ったら、想像で補わず `herdr agent`・`codex --help`・`~/.codex/models_cache.json` で実際を確認する。

## 待機中の判断

- **ファイルが未変更でも失敗と判断しない。** Codex は数分から十数分を調査に使ってから書き始める（実運用では開始3分後はまだ調査中だった）。
- 完了通知を受け取る前に、検収と最終報告を終えない。
- 待機中は同じ作業ツリーを触らない。**書き込みを伴う委任を同一作業ツリーで並列実行しない。** ペインを分けても作業ツリーは共有されるので、ペインの分離は並列化の根拠にならない。書かせる並列化には別の worktree / workspace を使い、`--cwd` をそちらへ向ける。
- 読み取りだけの委任（`-s read-only` で起動した調査・レビュー）は同じ作業ツリーで並走してよい。互いの結果を突き合わせたい調査は、むしろ分けて同時に走らせる。

## 段と残量を確かめる

起動したペインの Codex へ `/status` を送ると、適用中のモデルと推論量、週次の残量が返る（`Model: gpt-5.6-luna (reasoning none, summaries auto)` / `Weekly limit: 93% left (resets 16:53 on 18 Aug)`）。ローカルのUIコマンドなのでターンを消費しない。週次の残量は `sol` の許可を求めるときの材料になる（`ordering.md`）。委任の前後で読めば、その発注が実際にどれだけ使ったかも分かる。

**フッターの表示を段の確認に使わない。** `-c model_reasoning_effort=none` で起動したペインが、フッターには `gpt-5.6-luna default fast` と出しながら `/status` では `reasoning none` を返した。起動直後のバナーは `/status` と一致する。

## 報告を回収する

```bash
herdr agent read <名前> --source recent-unwrapped --lines 600
```

`--no-alt-screen` で起動していれば、セッション開始時のバナーまで遡って読める。幅は精度に影響しない（`recent-unwrapped` がソフトラップを繋ぎ直す）。回収できたのは実測で200行台なので、これを超える報告は分割して依頼する。

**終端マーカーを依頼文に入れない。** 完了の検知は herdr の仕事で、`--wait` が状態として返すので判定が二重になる。取りこぼしの検出にも使えない。読み取りは常に下端が基準なので、失われるのは先頭である。機械的に判定したいならマーカーは報告の**先頭**へ置く。

**ペインの記録は証拠ではない。** 見えているのは Codex が描いた画面であり、コマンドの生出力ではない。Codex はツール出力を `… +464 lines` のように畳むので、畳まれた部分は読めない。報告と画面が食い違ったら、どちらも信じずに、出力が短くなる形で追試させる（実害の記録は `evidence.md`）。実行ログの中身も Codex の内部状態であって成果物ではない。検収は画面でもログでもなく `git diff` で行う（`review.md`）。

## 承認を求められたとき

`blocked` が返ったら、`agent get` と `agent read --source detection` で何を聞かれているか読む。

**ディレクターは承認を代行しない。** Claude Code のclassifierが `send-keys` による承認の代理入力を止める。実際に止められた操作は3つ。Codex へ「サンドボックス外への権限昇格を要求して」と指示する発注、承認プロンプトへ `send-keys y` で承認を入力する操作、権限昇格の文言を含むヒアドキュメント。

却下は通る。`herdr agent send-keys <名前> esc` で却下でき、実測ではファイルは作られなかった。したがって承認が必要な場面は、見えているペインでユーザーが押す。ディレクターは何を求められているかをユーザーへ伝えて待つ。

却下した直後は Codex が「どうするか指示して」で待つため、`agent_status` は `blocked` のままである。通常の `agent prompt` を送ると `idle` に戻る。

## スレッドを分ける判断と片付け

新しい依頼は新しいエージェントで出す（`../SKILL.md`）。同じスレッドへ続けるのは、それまでのやり取りが作業の前提になる場合に限る。

- 検収で見つけた不備の差し戻し
- 直前の変更を踏まえた追加作業で、その調査を引き継ぐほうが速いもの
- 依頼文へ書き写すには大きすぎる文脈（長い調査の結果など）を土台にする作業

迷ったら分ける。判定はその文脈を依頼文へ数行で書けるかで足りる。書けるなら新しいスレッドへ渡す。

差し戻しは同じ名前へ `agent prompt` を送るだけで同じスレッドが続く。明示的に再開する操作は要らない。送る前に `agent_status` が `idle` か `done` であることを確認する。`blocked` のまま送ると、返ってきた `blocked` が新しい承認か直前の承認かを区別できない（`state_change_seq` が進んだかで判定する）。

終わったら `/quit` を送り、自分が作ったペインだけを閉じる。畳まずに増やすと、ペインが埋まるうえに、同一作業ツリーで別の Codex が走る事故も起きる。`agent_session.value` が Codex のセッションIDで、`/quit` 時に表示される `codex resume <UUID>` と一致する。あとで文脈が要ると分かったときはここから再開できるので、長い作業では控えておく（手順は `recovery.md`）。

## ネットワークとローカルバインド

Codex の workspace-write サンドボックスは既定でネットワークを閉じる。macOS の Seatbelt が `127.0.0.1` への bind まで拒否するため、`@cloudflare/vitest-pool-workers` の workers プール（workerd がループバックを listen する）と `wrangler dev` が動かない。失敗の見え方が厄介で、vitest は起動できたプールの件数だけを passed として表示するので、workers プールが落ちても「Tests 36 passed」と出る。Codex はこれを成功として報告した。

`herdr agent start` の `--` 以降に `-c sandbox_workspace_write.network_access=true` を渡すと、**そのペインのセッションだけ**開く。ループバックだけを開ける設定は存在しないので、外向きも同時に開く。

**`~/.codex/config.toml` へは書かない。** グローバルなので全 Codex 実行（TUI 含む、クライアント案件のリポジトリ含む）で外向きが開き、戻し忘れがそのまま恒久設定になる。

運用は次のとおり。

- ループバックを要する検証（workers プール、`wrangler dev`、通し実行）が発注に含まれるなら、起動時に付ける。ユーザーの方針で、これは都度の確認を要しない（2026-08-09）。外向きも開くが、それを理由に付けるのをためらわない。付けないまま出すと、Codex は一度も実行できないテストを論理だけで書くことになり、差し戻しが増える。
- 要らない発注には付けない。実装とサンドボックス内で完結する検査までを委任する形を崩さない。
- 開けたペインは検証が終わったら閉じる。同じ作業の続きでも、ネットワークが要らなくなったら開いたまま使い回さない。露出を絞るなら専用 worktree のペインに限定する。
- 開けた事実は報告に書き、trial-log にも残す。
- 付けなかった発注では、`<verification>` にサンドボックスで完走するコマンドだけを書き、フルスイートはディレクター側で実行すると明記する（`ordering.md`）。いずれの場合も、テストを追加させたら件数はディレクター側で数える（`review.md`）。Codex 側の実行は二重確認の片方でしかない。

開けている間の代償は、Codex が全ディスクの読み取りを持つことにある。1Password でマウント中の `.env` も読め、リポジトリ内容や取得ページ経由の prompt injection による持ち出し経路が増える。プロキシを併用しない限り通信先は制限されない。

なお、Codex へ「サンドボックス外への権限昇格を要求して」と指示する発注はclassifierに止められる。設定で開けるかどうかと、Codex に昇格を求めさせることは別の話で、後者は経路として使えない。
