# マージ後の後処理

`cleanup.sh` を実行し、出力をユーザーへ取り次ぐ。判断は全てスクリプト側にあるので、Claudeは実行と報告だけを担う。

```bash
bash ~/.claude/skills/post-merge-cleanup/cleanup.sh $ARGUMENTS
```

引数があれば対象ブランチとして渡す。なければスクリプトが現在のブランチから決める。

## なぜスクリプトなのか

マージ判定、squash/rebaseマージの見分け、upstream先行で `-d` が拒否るケースの切り分けは分岐が細かい。外したときの損失が未pushコミットの消失なので、指示の遵守に委ねず決定表をスクリプトへ置いた。`-D`（強制削除）と `stash` はスクリプトに存在しないため、そもそも実行され得ない。

## 終了コードの扱い

| コード | 意味 | Claudeの動き |
|---|---|---|
| 0 | 完了 | 出力をそのまま報告する |
| 2 | 前提を満たさず着手しなかった（作業ツリーが汚れている、対象が見つからない等） | stderrの理由を伝え、指示を仰ぐ |
| 3 | 途中で失敗した（切り替え、`--ff-only` の失敗など） | stderrの理由を伝えて止まる。ブランチは削除されていない |
| 4 | デフォルトブランチへは戻ったが、削除しなかったブランチがある | 「未削除」の行をそのまま伝える |

`-D` が要る状況（squash/rebaseマージ）は終了コード4で報告される。**Claudeが代わりに `-D` を打たない。** ユーザーへ可否を尋ね、明示的な指示があったときだけ実行する。
